# Product

## Register

product

## Platform

Native desktop (Windows first, with Linux and macOS support paths)

## Users

Players launching games that use Certael protected play. They may be waiting impatiently, uncertain whether a game has frozen, or concerned when a security check fails. Game publishers are a secondary audience because they supply the signed registration, branding, update policy, and repair path shown by the Agent.

## Product Purpose

Certael Agent verifies an approved local game build, establishes a private channel with the game, and waits for authoritative server admission before reporting a protected session. The launch surface makes every meaningful wait truthful and understandable, then either gets out of the player's way or offers a bounded recovery path. Success means players can distinguish checking, launching, waiting for admission, protected readiness, and failure without weakening the server-authoritative security model.

## Positioning

A transparent, user-mode integrity companion that explains what it is checking and never claims protection before the authoritative server proves it.

## Brand Personality

Precise, calm, and reassuring. The Agent should sound technically credible without speaking like a security operations center, alarming the player, or pretending that local evidence is authoritative.

## Anti-references

No neon security theater, alarm-heavy red dashboards, fake progress, premature “Protected” claims, glassmorphism, generic card grids, marketing-page composition, or unexplained risk graphics.

## Design Principles

- Make every progress statement correspond to completed or active work.
- Treat waiting as an understandable sequence, not an indeterminate freeze.
- Reserve “Protected” for verified server admission and a matching signed build.
- Make failures actionable while preserving protected-mode policy boundaries.
- Let verified game branding orient the player without allowing remote tracking or spoofable assets.

## Accessibility & Inclusion

Meet WCAG 2.2 AA. All states, progress, and severity must remain understandable without color; keyboard operation, visible focus, reduced motion, zoomed text, screen-reader semantics, and clear plain-language failure explanations are mandatory.
